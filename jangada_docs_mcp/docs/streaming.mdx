Receba tokens incrementais com `stream()` (sync) ou `astream()` (async).

```python
for token in llm.stream("Conte sobre {{x}}", x="João Pessoa"):
    print(token, end="")
```

```python
async for token in llm.astream("..."):   # ex.: FastAPI StreamingResponse
    ...
```

## Stream com tools, tokens e custo (`stream_complete`)

`stream()`/`astream()` entregam só texto. Num agente — o modelo escreve e, no
meio, pede ferramentas — use `stream_complete()`/`astream_complete()`: eventos
`text` enquanto a resposta é gerada e, no fim, um `done` com a `Completion`
completa, igual à de `complete` (`tool_calls`, `usage`, `cost`, `finish_reason`).

```python
from jangada_ai import LLM

llm = LLM("anthropic", "claude-sonnet-5-5")

async for ev in llm.astream_complete("Crie o arquivo de boas-vindas", tools=[escrever_arquivo]):
    if ev.type == "text":
        print(ev.text, end="", flush=True)      # aparece enquanto o modelo escreve
    else:  # "done"
        comp = ev.completion
        for call in comp.tool_calls:             # as tools pedidas, como no complete
            ...
        print("\ncusto:", comp.cost)
```

- Aceita os mesmos argumentos de `complete` (`tools=`, `tool_choice=`,
  `mcp_servers=`, `history=`, `files=`, `params=`…).
- **Streaming de verdade** em Anthropic, OpenAI, Azure e DeepSeek. Nos demais
  (e na Responses API da OpenAI) a chamada é a normal e o texto chega num pedaço
  só, seguido do `done` — nada de custo ou tool call perdido.
- Retry e fallback antes do primeiro evento, como no `stream`. O `done` é
  reportado à observabilidade com a capability `streaming`.
- Guardrail de saída e cache não se aplicam (o texto já saiu).

## Retry e fallback no streaming

O retry e o fallback acontecem **antes do primeiro token**: se a abertura do
stream falhar com erro transitório, a jangada tenta de novo (backoff) e, se
preciso, cai para o próximo candidato — tudo antes de você receber qualquer
conteúdo. Depois que o primeiro token sai, o stream segue até o fim.

Veja [Retry e fallback](/docs/retry-fallback) para a política completa.

## Observações

- `stream()`/`astream()` aceitam os mesmos `system=`, `history=`, `images=`,
  `files=` e `params=` das outras chamadas.
- Para custo e tokens use as chamadas não-stream (`complete`/`parse`), que
  retornam `usage`/`cost` na resposta — veja [Custo e tokens](/docs/cost).

## O que mudou na 1.9.0

- Chunks sem conteúdo (ex.: o primeiro chunk da Azure com o filtro de conteúdo)
  não quebram mais o stream, e a conexão é fechada se você parar de consumir o
  iterador no meio.
- Depois do stream, o provider guarda `usage` e `finish_reason` em
  `llm.provider.last_stream` (OpenAI, Azure, DeepSeek, Mistral, Ollama). É por
  instância: com várias threads usando o mesmo `LLM`, leia logo após o stream.
- O stream é reportado à [observabilidade](/docs/observability) ao final.
- Com tools nativas, o stream emite só o texto (Anthropic/Gemini/OpenAI); em
  Mistral e Ollama, stream + tools nativas levanta `UnsupportedError`.
