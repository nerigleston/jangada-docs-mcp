With fallback and a template:

```ts
import { LLM } from "jangada-ai";
import "jangada-ai/node"; // loads the project's .env

const llm = new LLM("openai", "gpt-4o-mini", {
  fallbacks: [new LLM("anthropic", "claude-haiku-4-5")],
});
const comp = await llm.complete("Hi, {{ name }}!", { variables: { name: "Ana" } });
console.log(comp.text, comp.usage, comp.cost);
```

Current version: 1.0.5 (npm). The `VERSION` constant exported by the package
holds the same number.

## What's in the package

The source is TypeScript. The published package is JavaScript in two formats,
ESM (`import`) and CommonJS (`require`), with the types (`.d.ts`) included. It
works in plain JS projects; in TypeScript you get autocomplete and type checking
without installing any `@types` package.

It runs on Node 22 or newer, Bun, Deno and edge runtimes (Cloudflare Workers,
Vercel Edge). The core does not use the file system or any `node:*` module.
What depends on Node (reading files, loading `.env`, starting an HTTP server)
lives in the `jangada-ai/node` subpath.

| Import | What it has |
| --- | --- |
| `jangada-ai` | `LLM` (`complete`, `parse`, `stream`, `streamComplete`, `embed`, `transcribe`, `ocr`), templates, retry and fallback, normalized errors, cost, profiles, tools and native tools, vision and documents, cache, guardrails, `Agent`, `Squad`, `Flow`, `Graph`, `GeminiInteractions`, observability |
| `jangada-ai/node` | `loadEnv`, `readImage`, `readDocument`, `readAudio`, `runInSession`, `serveMcp`, `serveA2a`. Importing it loads `.env` |
| `jangada-ai/mcp` | `MCPClient`, `runAgent`, MCP server and Code Mode |
| `jangada-ai/rag` | `RAG`, chunking, rerank and stores (memory, pgvector, MongoDB) |
| `jangada-ai/eval` | `Dataset`, `Evaluator`, `evaluate` |
| `jangada-ai/prebuilt` | ready-made tools: calculator, date and time, CPF/CNPJ, CEP, Wikipedia, Brave, Tavily, weather, HTTP |
| `jangada-ai/a2a` | web-standard A2A server (`Request` → `Response`) |

## SDKs loaded on demand

The provider SDKs (`openai`, `@anthropic-ai/sdk`, `@google/genai` and others)
are optional `peerDependencies`. Install only the ones you use. Each provider's
adapter is loaded on the first call, and the SDK comes in through
`await import()` inside it. That is why `import "jangada-ai"` works with no SDK
installed, and an app that only uses OpenAI never loads the Anthropic adapter.

If the SDK is missing, the error shows up on the first call, with the install
command in the message (`Instale o SDK da OpenAI para usar 'openai': npm install openai`).
The full peer table is in [Getting started](/en/docs/js/getting-started).

## Parity with Python

Version 1.0 covers what the Python library does: 11 providers, retry and
fallback, structured output, tools and native tools, streaming, vision and
documents, transcription, embeddings, OCR, cost, cache, guardrails, agents, MCP,
RAG, Gemini Interactions, A2A, observability and eval.

The test cases for templates, error classification, cost calculation, profiles
and the price catalog are generated by the Python library and run against the
port, so both sides give the same result. RAG uses the same schema in Postgres
and MongoDB: Python and JS can read and write the same database.

The differences come from the language: async-only API, camelCase names,
template variables in an object, Zod instead of Pydantic, `signal` to cancel.
The full list is in [Differences from Python](/en/docs/js/differences).
