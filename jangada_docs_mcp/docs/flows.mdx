A jangada traz duas formas de encadear chamadas, ambas agregando `usage`/`cost`.

## Flow — sequencial

`Flow` encadeia passos: a saída de um vira variável do próximo.

```python
from jangada_ai import LLM, Flow

llm = LLM("openai", "gpt-4o-mini")

flow = (
    Flow(llm)  # LLM padrão dos passos
    .step("rascunho", "Escreva um parágrafo sobre {{tema}}.")
    .step("revisao", "Revise e melhore:\n{{rascunho}}")
)

res = flow.run(tema="jangadas do Nordeste")   # async: await flow.arun(...)
print(res["revisao"])   # saída de um passo pelo nome
print(res.last)         # saída do último passo
print(res.cost)         # custo agregado de toda a cadeia
```

Cada passo referencia as saídas anteriores pelo nome via template `{{ }}`.
`step()` aceita ainda `system=`, `llm=` (outro modelo só naquele passo),
`output=` (nome da variável, se diferente do passo) e `schema=` (usa `parse()`;
leia com `res.parsed("passo")`).

## Graph — roteamento condicional + paralelo

`Graph` permite ramificar (roteamento condicional) e executar nós em paralelo
(core async), juntando os resultados.

```python
from jangada_ai import LLM, Graph

rapido = LLM("groq", "openai/gpt-oss-20b")
forte = LLM("anthropic", "claude-sonnet-4-5")

g = Graph()
g.node("triagem", rapido, "Responda só 'tecnico' ou 'geral': {{pergunta}}")
g.node("tecnico", forte, "Responda tecnicamente: {{pergunta}}")
g.node("geral", rapido, "Responda de forma simples: {{pergunta}}")
# roteamento condicional: o router recebe o contexto e devolve o próximo nó (ou None)
g.route("triagem", lambda ctx: "tecnico" if "tecnico" in ctx["triagem"].lower() else "geral")

res = g.run("triagem", pergunta="como funciona o handshake TCP?")  # async: await g.arun(...)
print(res.path)               # ex.: ['triagem', 'tecnico']
print(res[res.path[-1]])      # saída do último nó
print(res.cost)               # GraphResult agrega usage/cost

# paralelo + junção: os ramos rodam ao mesmo tempo e o join lê cada um pelo nome
g2 = Graph()
g2.parallel(
    "pesquisas",
    {
        "mercado": (rapido, "Analise o mercado de: {{tema}}"),
        "tecnica": (forte, "Analise a viabilidade técnica de: {{tema}}"),
    },
    join="sintese",
)
g2.node("sintese", forte, "Combine:\nMercado: {{mercado}}\nTécnica: {{tecnica}}")
print(g2.run("pesquisas", tema="app de corrida com IA")["sintese"])
```

Para encadear nós sem condição, use `g.then("a", "b")`.

### Fan-out robusto e observável (`parallel`)

`parallel` aceita opções para produção:

```python
g.parallel(
    "analises", branches, join="sintese",
    on_error="skip",        # um ramo que falha não derruba o run (default: "raise")
    max_concurrency=4,      # teto de ramos simultâneos (evita rate limit)
    summarize=True,         # cada ramo resume a própria saída antes do join
)
```

- **`on_error="skip"`**: o ramo que falhar fica ausente do join (string vazia no
  contexto) e vai para `GraphResult.failures` (`{ramo: erro}`). O fan-out entrega o
  parcial em vez de perder o trabalho já pago dos outros ramos. Com `"raise"`
  (padrão) a primeira exceção derruba o run.
- **`max_concurrency=N`**: semáforo — no máximo N ramos rodam ao mesmo tempo.
- **`summarize`**: `True` (instrução padrão) ou uma instrução `str`. Corta o input
  do join (que lê todos os ramos e cresce O(N)); a chamada de resumo entra no
  `usage`/`cost`.

`GraphResult` também expõe **`durations`** (`{nó/ramo: segundos}`) — dá para medir
`max(ramos)` vs `t_join` diretamente, o diagnóstico que importa num fan-out.

## Custo agregado

`FlowResult` e `GraphResult` somam `usage` e `cost` de todas as etapas — útil
para observabilidade. Detalhes em [Custo e tokens](/docs/cost) e, para inspecionar
passo a passo, [Debug](/docs/debug).

## O que mudou na 1.9.0

- **`Flow.arun(**contexto)`**: versão assíncrona do `Flow`.
- **`Graph(max_steps=50)`**: teto de nós executados num `run`; um router cíclico
  que nunca termina levanta `RuntimeError` em vez de gastar sem limite.
- **Nó revisitado** (ciclo) ou step com nome repetido não sobrescreve o anterior:
  as visitas aparecem como `nome#2`, `nome#3` em `completions`/`durations`, e
  `usage`/`cost` somam todas. `parsed("nome")` devolve a última visita.
- **Ramos paralelos com `on_error="raise"`**: quando um ramo falha, os irmãos ainda
  pendentes são cancelados (antes continuavam rodando e gastando tokens).
- **Nomes reservados.** Nós, steps, ramos e variáveis de contexto não podem se
  chamar `system`, `history`, `params`, `tools`, `tool_choice`, `files`, `images`,
  `schema`, `prompt`, `mcp_servers` ou `self` — eles colidiam com os argumentos de
  `complete` e causavam erros estranhos. Agora levantam `ValueError` na hora.
- `then()`/`route()` num bloco paralelo levantam erro (antes eram ignorados em
  silêncio); `join` apontando para nó inexistente tem mensagem própria.
